## 1. What is Architect OS?

Architect OS is a **local-first AI Agent Control Plane**. Its purpose is to observe coding-agent runs, preserve project history and context, explain recorded changes, support resumption of interrupted work, and benchmark agents and context strategies. It sits above agents such as Codex and Claude Code rather than replacing them. (`AGENTS.md:3-8`)

The broader product description calls it an **AI Agent Control Plane, Project Intelligence System, Context Economy Engine, and Agent Engineering Workbench**. Its four product pillars are:

- Agent Flight Recorder
- Project Chronicle
- Context Economy
- Engineering Workbench, with distinct BUILD, LEARN, and RESEARCH modes

(`docs/PRODUCT.md:3-29`)

## 4. What major architecture boundaries must not be violated?

1. **Agent versus Architect ownership:** Agents retain ownership of conversations, code generation, native tools, sandboxes, permissions, and provider session behavior. Architect owns normalized history, timelines, context audit, resume/explain reports, benchmarks, and project memory. (`docs/ARCHITECTURE.md:37-44`)

2. **Normalized observer boundary:** Provider observers must translate provider evidence into normalized Architect events and persist through the Flight Recorder. Provider-specific formats must not leak into core storage. (`docs/ARCHITECTURE.md:46-60`)

3. **Transport, mapping, and persistence separation:** For live Codex, the receiver owns transport and run correlation, the observer owns mapping and privacy filtering, and persistence remains through the Flight Recorder. The recorder and SQLite schema are not provider-specific. (`docs/ARCHITECTURE.md:82-95`)

4. **Evidence fidelity:** Architect must never claim visibility beyond the evidence available at the active fidelity level. Session reports may not invent causes, recommendations, live state, or mastery. (`docs/ARCHITECTURE.md:97-102`, `docs/STATUS.md:39-46`)

5. **Local, Git-grounded context:** Git remains the repository ground truth. Context indexing is limited to tracked content; the cache stores metadata rather than prompts or complete source bodies, and context savings must not reduce correctness. (`AGENTS.md:37-45`, `docs/ARCHITECTURE.md:285-310`, `docs/EXECUTION_PROTOCOL.md:147-164`)

6. **No unapproved platform expansion:** The current boundary excludes unrelated milestones, global hooks, passive/background observation, scheduling, multi-agent runtime orchestration, and a web UI. BUILD, LEARN, and RESEARCH responsibilities should not be mixed without an explicit reason. (`AGENTS.md:10-15`, `AGENTS.md:23-35`)

7. **No unilateral product-direction changes:** A3 permits executing the approved roadmap; A4 product autonomy is disabled. Changing durable architecture, ownership, core infrastructure, privacy behavior, or roadmap scope requires a human decision. (`docs/EXECUTION_PROTOCOL.md:7-31`, `docs/EXECUTION_PROTOCOL.md:99-116`)
