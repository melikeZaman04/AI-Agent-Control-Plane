### 1. What is Architect OS?

Architect OS is a **local-first AI Agent Control Plane** that sits above external coding agents. It observes available agent activity, normalizes evidence, preserves project history, supports resuming and explaining recorded work, reduces repeated repository discovery, and provides benchmarking and controlled engineering labs (`AGENTS.md:3-7`; `docs/PRODUCT.md:5-25`).

It does not replace agent conversations, code generation, tools, sandboxes, permissions, or provider session behavior (`docs/PRODUCT.md:7-9`). It has three distinct modes:

- **BUILD:** develop real projects.
- **LEARN:** run controlled engineering labs.
- **RESEARCH:** compare agents, context strategies, and architecture decisions.

(`docs/PRODUCT.md:21-29`)

### 4. What major architecture boundaries must not be violated?

- **Agent versus Architect ownership:** Agents retain conversations, code generation, native tools, sandboxes, permissions, and provider sessions. Architect owns normalized history, project timelines, context audit, reports, benchmarks, and project memory (`docs/ARCHITECTURE.md:30-37`).

- **Provider isolation:** Provider-specific formats must be translated through observers into normalized Architect events and must not leak into core storage. Flight Recorder remains independent of provider observers (`docs/ARCHITECTURE.md:39-55`; `docs/ARCHITECTURE.md:57-66`).

- **Evidence fidelity:** Architect must never claim visibility beyond the active observer fidelity. Recorded observations must not be promoted into unobserved outcomes, causes, recommendations, or causal narratives (`docs/ARCHITECTURE.md:117-123`; `docs/GLOSSARY.md:26-31`).

- **Local-first ground truth:** Git and repository state remain authoritative. Optional knowledge providers may supplement them but cannot replace current Git/source evidence (`docs/GLOSSARY.md:111-113`; `docs/GLOSSARY.md:140-144`).

- **Context correctness:** Context savings must not reduce correctness. Raw prompts and complete source bodies must not be cached in the context index (`AGENTS.md:35-43`; `docs/ROADMAP.md:135-146`).

- **No architectural scope expansion under A3:** A4 product autonomy is disabled. New milestones, product direction changes, global hooks, background observation, schedulers, multi-agent runtime orchestration, and a web UI cannot be introduced under the current authority (`AGENTS.md:20-32`; `docs/EXECUTION_PROTOCOL.md:14-29`).

- **Preserve core infrastructure boundaries:** The Observer/FlightRecorder boundary and SQLite schema are documented as preserved; no new runtime service, dependency, scheduler, or multi-agent execution infrastructure was added (`docs/STATUS.md:39-46`).

- **Keep product modes distinct:** BUILD, LEARN, and RESEARCH responsibilities should not be mixed without an explicit reason (`AGENTS.md:9-15`).
