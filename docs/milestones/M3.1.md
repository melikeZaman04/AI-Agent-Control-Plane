## Implementation and validation

Design is canonical in [ARCHITECTURE](../ARCHITECTURE.md#m31--project-chronicle-foundation)
and [ADR-004](../adr/ADR-004-chronicle-foundation.md). The bounded slices were
baseline repair, protocol/bootstrap, read-only domain/query implementation,
end-to-end tests, self-review and documentation/exit validation.

| Exit evidence | Validation |
|---|---|
| Domain and association | ChronicleEpisode identifies project/root/run/kind; lifecycle test checks begin/end/status against source rows/events. |
| Deterministic facts and provenance | ObservationFact counts retain exact source event IDs, provider/fidelity and unknown statuses; IDs resolve to SQLite payloads and FlightRecorder events. |
| Local minimal storage | No schema addition; read-only source snapshot; test compares database dumps before and after querying. Missing databases are not created. |
| Idempotency | Repeated queries give identical objects/JSON; new evidence changes facts while retaining episode identity; backed-up database gives identical JSON. |
| Chronology | Tests cover timezone equivalence, full-run-ID ties, unknown starts and event insertion-ID ties. |
| Provider independence | Actual live-format ClaudeObserver/CodexObserver outputs pass through FlightRecorder and SQLite to Chronicle; arbitrary provider and all eight event types are tested. |
| Evidence restraint | Legacy payloads are excluded, unknown test status stays unknown, successful generic tools stay tools, and arbitrary metadata is not promoted. |
| Ownership/integrity | Wrong project/shared databases, absent registration, invalid normalized events, mismatched run IDs and duplicate IDs are tested. |
| Existing behavior | Shared timeline decoder extraction preserves ordering and legacy handling; all FlightRecorder and existing regressions pass. |
